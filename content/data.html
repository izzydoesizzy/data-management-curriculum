Practice data: Riverside Community Services

A completely fictional agency with 300 clients, 14 staff and 18 months of services (April 2025 to August 2026). It's shaped like a real case-management export, messiness included. No real people are in it.

How the tables connect

This is the most important picture in the course. Each table has an ID column that links it to the others. You'll use these links in Excel (XLOOKUP) and in Power BI (relationships).

                  ┌──────────────┐
                  │   clients    │
                  │  ClientID    │
                  │  Program     │
                  └──────┬───────┘
                         │ one
                         ▼ many
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│service_codes │  │   services   │  │   workers    │
│ ServiceCode  ├─►│ ClientID     │◄─┤ WorkerID     │
│ Category     │  │ ServiceCode  │  │ Name, Role   │
│ UnitCost $   │  │ WorkerID     │  └──────────────┘
└──────────────┘  │ ServiceDate  │
  one → many      └──────────────┘    one → many

Notice what's not in the services table: there's no dollar amount. The cost lives in the price list (service_codes.csv). To answer "how much did we spend per client?" you have to connect the two. That's exactly the skill this course teaches.

The deliberate mess in services_raw.csv

Real exports are never clean. You'll fix these in Week 3 (by hand) and Week 7 (automatically):

  • Some service codes have extra spaces: "HV01 " instead of "HV01"
  • Some are lower case: "hv01"
  • Some rows were exported twice (exact duplicates)
  • Some rows have a blank service code (unusable for costing)
For the curious: how this data was made

The files are generated by a small Python script (data/generate.py in the project's GitHub repository) with a fixed random seed, so everyone gets identical data and identical answers. The answer key the checkpoints use was double-checked independently.
